acceptance_criteria: The idiom 'mt=$(stat -f %m PATH 2>/dev/null || stat -c %Y PATH)' selects the platform on EXIT STATUS, which is wrong: GNU stat's -f is filesystem mode, so on Linux it can SUCCEED with non-numeric output, the fallback never runs, and the arithmetic that follows treats that word as a variable name — observed in CI as 'lib/common.sh: line 466: File: unbound variable' under set -u, taking down lock_acquire and cascading into the drive, gc, epoch-fencing and resume tests. The correct form already exists in this repo: libexec/orchid-start:162-165 selects on the RESULT, falling back when mt is empty or non-numeric, with a comment explaining exactly this hazard. Apply that form everywhere the raw idiom remains: lib/common.sh:465, libexec/orchid-doctor:439, libexec/orchid-answer:53, libexec/orchid-jobs:224 and libexec/orchid-jobs:407. Add a focused test that a non-numeric stat result cannot reach arithmetic. This is the same class as lesson L016: a correct pattern existed and nothing made it apply beyond the file that discovered it.
