acceptance_criteria: Lesson L017: the implementer profile denies on the command STRING, not the binary — no bash, no bash -n, no shellcheck, no writing git, and any command containing a literal dollar sign, a semicolon, parenthesis grouping or process substitution is refused. So a lint gate's findings are invisible to the actor asked to fix them. Measured cost in r-001: T005 was told twice to fix two ShellCheck findings in a file it had written; one attempt wrote a documentation paragraph and the next edited eighteen lines, neither touching either offending line, because it could not see them. Make the rework path carry the exact 'file:line: RULE: message' text into the brief automatically wherever a lint or verification failure produced it, AND record lint, pin and chmod fixes as an explicit operator hand-off in PROTOCOL.md rather than a convention nobody enforces. These are NOT alternatives: the constraints require both. Carrying exact locations makes a routed fix satisfiable when the operator does it; recording the hand-off is what stops it being routed to an actor that cannot act on it. Whichever is chosen must remove the possibility of routing an unsatisfiable instruction. Add coverage that a lint failure's exact locations reach the guidance the implementer receives. MANDATORY OPERATOR HAND-OFFS for this task, not optional: the implementer profile cannot execute anything (lesson L017), so it must NOT re-pin Formula/orchid.rb, must NOT chmod any file, and must NOT be asked to run a verifier, shellcheck or bash. It must instead state plainly in its report that the formula pin is stale, that verification was not run, and — ONLY IF this task actually adds a new executable — that its mode needs setting. Do not report a chmod hand-off when no executable was added. The operator performs those three and records them. THE HAND-OFF NEEDS A PLACE IN THE PROCEDURE, not just a sentence in a task spec. Today the operator performs the pin, the chmod and any lint fix by habit, between the implementer's envelope reconciling and orchid verify running — nothing in PROTOCOL.md names that point, so a driver or a less careful operator would verify a candidate that was never going to pass and burn an attempt. Define the pause explicitly in THE TICK's implementing arm: after the envelope reconciles and before verification, the operator-owned mechanical steps happen and are journaled. Say what a deterministic driver should do when it reaches that point (stop at a named boundary rather than verify-and-fail), so the same rule holds whether a human or the driver is walking the task. THE BOUNDARY NEEDS A DURABLE ACKNOWLEDGEMENT AND A RESUME RULE, or it becomes an infinite loop: if the tick stops at the hand-off point, something must record that the operator actually performed the pin, the chmod or the lint fix, so a resumed session or a second driver pass does not stop at the same point forever and does not proceed as though it were done. Define where that acknowledgement lives (a journaled entry, a task field, or the boundary record itself), what clears it, and what a resume does when it finds the boundary already satisfied versus still outstanding. Cover it with a focused test that a second pass after an acknowledged hand-off proceeds, and a second pass without one stops again. BIND THE ACKNOWLEDGEMENT TO A COMMITTED candidate_sha, not to a task or a moment: an operator hand-off performed against one candidate must not be read as satisfied for a different one. State what happens when orchid merge's rebase arm moves candidate_sha underneath an acknowledged hand-off — the acknowledgement must be invalidated the same way review evidence is (INV-07), not silently inherited by the rebased tree. RESOLVE THE APPARENT CONTRADICTION EXPLICITLY: this task both routes exact lint locations into implementer guidance and declares lint fixes operator-owned. Both are intended and the spec must say why — the locations travel with the guidance so that WHOEVER acts has them and the record shows what was wrong, while the ACT of running a linter or committing its fix stays with the operator under L017. Write that distinction into PROTOCOL.md so it does not read as a contradiction to the next person.
